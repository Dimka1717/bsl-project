# Сценарий: УТ 10.3 + Контур.Маркировка + EME для документа «Поступление товаров и услуг»

## Цель

Реализовать сквозной процесс для **стандартного** документа `ПоступлениеТоваровУслуг`:

1. Из Контур.Маркировки (через ЭДО) получить коды маркировки по входящему документу.
2. Записать коды в структуру, привязанную к строкам ПТУ.
3. Передать коды в EME.
4. Получить из EME факт сканирования (принятые коды).
5. Сверить `Контур vs EME` по каждой строке ПТУ и подсветить:
   - 🟩 зелёный — полное совпадение;
   - 🟥 красный — есть расхождения.

---

## Что уже есть в кодовой базе (опора)

### Контур.Маркировка
- Создание/поиск документа учета по документу 1С:
  - `ВзаимодействиеКонтурМаркировка.СоздатьДокументУчетаПоДокументу1С(...)`
  - `ВзаимодействиеКонтурМаркировка.НайтиДокументУчетаПоДокументу1С(...)`
- Обмен с Контуром:
  - `ВзаимодействиеКонтурМаркировка.ВыполнитьОбменПоОрганизации(...)`
- Получение кодов по сверке на приемке:
  - `ВзаимодействиеКонтурМаркировка.КодыДокументаИзСверкиНаПриемке(...)`
- Актуализация статусов кодов:
  - `ВзаимодействиеКонтурМаркировка.ОбновитьСтатусыКодовДокумента(...)`

### EME
- Экспорт документа поступления: `eme/EmeWmsЭкспортПоступленийТоваровУслуг`.
- Импорт факта приемки: `eme/EmeWmsИмпортПоступленийТоваровУслуг`.
- Базовые преобразования марки: `EmeWmsУтилиты.КодМаркиВЗначениеБезСкобок()`, `...СоСкобками()`.

## Предлагаемая структура хранения маркировки в УТ 10.3

Рекомендуется завести **информационный регистр** `КонтурEMEМаркиПоступления` (периодический не нужен).

### Измерения
- `ДокументПоступления` (ДокументСсылка.ПоступлениеТоваровУслуг)
- `НомерСтрокиТовары` (Число)
- `Номенклатура` (СправочникСсылка.Номенклатура)
- `Характеристика` (если используется)
- `Серия` (если используется)
- `КодМарки` (Строка, 200)

### Ресурсы/Реквизиты
- `Источник` (Перечисление: Контур / EME)
- `СтатусСверки` (Перечисление: Совпадает / ЛишнийВEME / НеСканированВEME)
- `ДатаЗагрузки` (Дата)
- `Комментарий` (Строка)

> Почему так: хранение «по одному коду на запись» упрощает дедупликацию, сравнение множеств и диагностику ошибок.

## Алгоритм процесса (по шагам)

## Шаг 1. Получить марки из Контур.Маркировки по ПТУ

1. На основании `ПоступлениеТоваровУслуг.Ссылка` найти/создать ДокументУчета.
2. Выполнить обмен по организации.
3. Вызвать получение кодов сверки на приемке (`КодыДокументаИзСверкиНаПриемке`).
4. Сопоставить коды со строками ПТУ по ключу:
   - Номенклатура + Характеристика/Серия + Количество.
5. Записать коды в регистр `КонтурEMEМаркиПоступления` с `Источник = Контур`.

### Валидации
- Если документ в Контуре не найден — блокирующее сообщение.
- Если код не сопоставился ни одной строке ПТУ — писать в `Комментарий` и пометить как «требует ручной разбор».

---

## Шаг 2. Передать марки в EME

1. При экспорте ПТУ в EME забрать из регистра коды `Источник = Контур`.
2. Преобразовать формат кода к согласованному с EME (`plain` или `Base64`).
3. Передать в структуре `sscc.true_sign` на каждую единицу маркируемого товара.
4. В `sscc` обязательно передавать `goods_id`, `lot_no`, `quantity`, `true_sign`.

---

## Шаг 3. Получить факт сканирования из EME

1. В импорте receipt из EME получить `sscc.true_sign`.
2. Нормализовать код (единый формат).
3. Записать в тот же регистр с `Источник = EME`.

---

## Шаг 4. Сверка Контур vs EME

Для каждой строки ПТУ:

- `КонтурКоды` = множество кодов из регистра (`Источник=Контур`).
- `EMEКоды` = множество кодов из регистра (`Источник=EME`).

Статусы:
- если множества равны -> `Совпадает`;
- если `КонтурКоды - EMEКоды` не пусто -> `НеСканированВEME`;
- если `EMEКоды - КонтурКоды` не пусто -> `ЛишнийВEME`.

Итоговый цвет строки:
- зеленый — только `Совпадает`;
- красный — любое отклонение.

---

## Шаг 5. Подсветка строк в форме ПТУ

В форму документа добавить вычисляемую колонку, например `ЦветМаркировки`/`СтатусМаркировки`.

Правило отображения:
- `СтатусМаркировки = "ОК"` -> зеленый;
- иначе -> красный.

Технически это можно сделать через:
- условное оформление строк ТЧ `Товары`;
- либо отдельную колонку-иконку статуса.

---

## Псевдокод сервиса сверки

```bsl
Функция СверитьМаркиПоступления(ПТУСсылка) Экспорт

    Результат = Новый Структура;
    Результат.Вставить("Строки", Новый ТаблицаЗначений);

    Для Каждого СтрТовар Из ПТУСсылка.Товары Цикл
        КонтурКоды = ПолучитьКоды(ПТУСсылка, СтрТовар.НомерСтроки, "Контур");
        EMEКоды    = ПолучитьКоды(ПТУСсылка, СтрТовар.НомерСтроки, "EME");

        НеСканировано = РазностьМножеств(КонтурКоды, EMEКоды);
        Лишние        = РазностьМножеств(EMEКоды, КонтурКоды);

        Статус = ?(НеСканировано.Количество() = 0 И Лишние.Количество() = 0, "ОК", "Ошибка");

        Нов = Результат.Строки.Добавить();
        Нов.НомерСтроки = СтрТовар.НомерСтроки;
        Нов.Статус = Статус;
        Нов.НеСканировано = НеСканировано.Количество();
        Нов.Лишние = Лишние.Количество();
    КонецЦикла;

    Возврат Результат;

КонецФункции
```

## Тесты (что обязательно прогнать)

## A. Позитивные
1. **Полное совпадение**
   - Контур дал 10 кодов, EME вернул те же 10.
   - Ожидание: все строки зеленые.

2. **Частично маркируемый документ**
   - В ПТУ 3 строки: 2 маркируемые, 1 немаркируемая.
   - Ожидание: проверка/цвет только для маркируемых строк.

## B. Негативные
3. **Не досканировали**
   - Контур 10, EME 8.
   - Ожидание: красный, 2 кода в `НеСканированВEME`.

4. **Лишние коды**
   - Контур 10, EME 11.
   - Ожидание: красный, 1 код в `ЛишнийВEME`.

5. **Дубли в EME**
   - EME прислал повторяющиеся коды.
   - Ожидание: в хранилище дубликаты не ломают итог (сравнение множеств).

6. **Форматный конфликт (Base64/plain)**
   - Контур-коды plain, EME вернул Base64.
   - Ожидание: после нормализации сравнение корректно; без нормализации — красный и диагностический комментарий.

## C. Интеграционные
7. **Нет связи с ЭДО/Контур**
   - Ожидание: понятная ошибка, документ не переводится в «ОК».

8. **Повторный обмен**
   - После повторной загрузки коды не дублируются, старые статусы корректно пересчитываются.

## Минимальный план внедрения

1. Добавить регистр `КонтурEMEМаркиПоступления`.
2. Сделать серверный модуль-оркестратор, например `КонтурEMEМаркировкаПоступлений`:
   - `ЗагрузитьИзКонтура(ПТУСсылка)`
   - `ПодготовитьКЭкспортуEME(ПТУСсылка)`
   - `ЗагрузитьИзEME(ПТУСсылка, ERPData)`
   - `Сверить(ПТУСсылка)`
3. Добавить команду в форму ПТУ: «Проверить маркировку (Контур/EME)».
4. Добавить условное оформление строк ТЧ `Товары` по результату `Сверить`.
5. Прогнать тесты A/B/C.
